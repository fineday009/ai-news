## 2. vercel-labs/agent-browser

⭐ 47.7k（今日 +815）· Rust · [链接](https://github.com/vercel-labs/agent-browser)

**是什么**：给 AI Agent 用的浏览器自动化 CLI：打开页面、以无障碍树读取内容，并在 shell 里操作页面元素。

**What it is**: Browser automation CLI for AI agents: open pages, read them as an accessibility tree, and act on elements from the shell.

**为什么值得关注**：原生 Rust CLI，`snapshot` 把页面压成紧凑文本，并给每个元素一个 `@e1` 这样的引用，Agent 按引用操作后再读一次页面确认结果。它的细节很务实：目标被遮挡、隐藏或禁用时点击会直接失败，而不是假装成功，这正好堵住 Agent 自动化常见的"以为点到了"问题。每个 `--session` 有独立的守护进程和浏览器，也能接管已运行的 Chrome。

**Why it matters**: A native Rust CLI whose `snapshot` compresses a page into compact text with a ref such as `@e1` for each element; the agent acts on a ref, then reads the page again to confirm the result. The details are practical: a click fails outright when the target is covered, hidden or disabled instead of reporting success, closing off the classic "agent thinks it clicked" failure. Each `--session` gets its own daemon and browser, and it can also attach to a running Chrome.

## 4. ranxianglei/billion-context

⭐ 5,263（今日 +460）· TypeScript · [链接](https://github.com/ranxianglei/billion-context)

**是什么**：上下文压缩插件，让单个会话跑上一个月（数十亿 token），100K 的上下文窗口也够用。

**What it is**: A context-compression plugin for month-long single sessions (billions of tokens) with small context windows (100K is enough).

**为什么值得关注**：它以代理形式夹在 Agent 和模型 API 之间，向对话注入 `compress`、`decompress`、`search_context` 等工具，由模型自己决定何时压缩、压缩什么。和宿主自带的摘要不同，它的压缩是增量、可还原的，并且保护提示缓存前缀；README 称健康会话的前缀缓存命中率保持在 95–97%，"省 5 倍 token"也是项目自述。支持 Claude Code、OpenCode、dsh、Kimi 等多个客户端，还附了论文和第三方评测，适合长会话跑得起飞、账单也跟着起飞的人。

**Why it matters**: It sits as a proxy between the agent and the model API and injects tools such as `compress`, `decompress` and `search_context`, so the model itself decides when and what to compress. Unlike a host's built-in summarizer, compression is incremental, reversible and friendly to the prompt-cache prefix; the README reports a 95–97% prefix-cache hit rate for healthy sessions, and "5× fewer tokens" is likewise the project's own claim. It supports Claude Code, OpenCode, dsh, Kimi and more, and ships a paper and third-party benchmarks, for anyone whose long sessions and bills keep growing together.

## 7. physicsdolphin/nv-uefi-unlocker

⭐ 2,123 · Rust · 创建于 2026-10-26 · [链接](https://github.com/physicsdolphin/nv-uefi-unlocker)

**是什么**：UEFI 预驱动 NVIDIA GPU 解锁工具，从 U 盘启动，解开张量计算限制后再进入 Windows、Linux 或其他系统。

**What it is**: A UEFI pre-driver NVIDIA GPU unlocker: boot from USB, lift the tensor-compute limits, then continue into Windows, Linux or any EFI-bootable system.

**为什么值得关注**：延续 gpu-unlock 掀起的"显卡解锁"热潮，把支持范围扩到 GTX 16 和 RTX 20/30/40 系，也不再依赖特定操作系统。它无需刷写 VBIOS，断电即恢复；README 汇总的实测称 FP16/BF16/TF32 吞吐最高约 2.6 倍，而 LLM 推理的提升小得多（prefill 最高 +19%、decode +5%）。这是在改动硬件底层状态，社区报告的结果因型号而异，使用前要先读兼容表和 FAQ。

**Why it matters**: It extends the unlock wave started by gpu-unlock to GTX 16 and RTX 20/30/40 cards and no longer depends on a specific OS. No VBIOS flash is needed and a power cycle restores the card; measurements collected in the README claim up to roughly 2.6× FP16/BF16/TF32 throughput, while LLM inference gains are much smaller (up to +19% prefill, +5% decode). It alters low-level hardware state and community results vary by model, so read the compatibility table and FAQ first.
