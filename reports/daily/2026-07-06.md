## 1. deepseek-ai/DeepSpec

⭐ 6.2k（近期新建，6/26 创建）· Python · [链接](https://github.com/deepseek-ai/DeepSpec)

**是什么**：DeepSpec 是一套用于训练与评测推测解码（speculative decoding）算法的全栈代码库。

**What it is**: DeepSpec is a full-stack codebase for training and evaluating speculative decoding algorithms.

**为什么值得关注**：推测解码是当下 LLM 推理加速的关键技术，但此前大多是分散的推理端实现，缺少「训练 + 评测」一体化的公开框架。DeepSeek 亲自下场把训练草稿模型、对齐目标模型、复现基准的全链路开源，几天就冲到 6k+ star，对做推理加速的研究者和工程团队是难得的地基。

**Why it matters**: Speculative decoding is a key lever for LLM inference speedups, but public work has been mostly scattered inference-side implementations with no unified train-plus-evaluate framework. DeepSeek open-sourcing the full pipeline — training draft models, aligning them to the target model, reproducing benchmarks — hit 6k+ stars within days and gives inference-acceleration researchers and engineering teams a rare shared foundation.

## 2. usestrix/strix

**是什么**：Strix 是一款开源的 AI 渗透测试工具，用于自动发现并帮助修复应用中的安全漏洞。

**What it is**: Strix is an open-source AI penetration testing tool to find and fix your app's vulnerabilities.

**为什么值得关注**：安全测试是 Agent 落地最实、也最容易验证价值的场景之一——漏洞要么复现得了要么复现不了。Strix 把 LLM 驱动的自动化侦察、利用尝试与修复建议打包成开源工具，本周持续高速涨星，说明「攻防自动化」正从演示走向工程团队的日常流水线。

**Why it matters**: Security testing is one of the most concrete and verifiable places to put agents to work — an exploit either reproduces or it doesn't. Strix packages LLM-driven recon, exploitation attempts, and fix suggestions into an open-source tool, and its sustained star growth this week signals that offensive-security automation is moving from demo to everyday engineering pipeline.

## 5. gastownhall/gastown

⭐ 16.4k（今日 +51）· Go · [链接](https://github.com/gastownhall/gastown)

**是什么**：Gas Town 是一个多智能体工作区管理器，可同时编排 Claude Code、Copilot、Codex 等多个编码 Agent 分头干活。

**What it is**: Gas Town is a workspace manager that orchestrates many AI coding agents (Claude Code, Copilot, Codex, and others) working on different tasks simultaneously.

**为什么值得关注**：单个 Agent 好用，20–30 个 Agent 并行就成了协调难题。Gas Town 用 git 支撑的 hook 持久化各 Agent 的工作状态，避免重启丢上下文，并以「Mayor 协调者 + convoys 工作单元 + 三层健康监控」的一整套机制实现可靠编排，甚至带有合并队列和跨机的联邦工作网络，是把「Agent 车队」工程化的认真尝试。

**Why it matters**: One agent is easy; 20–30 running in parallel is a coordination problem. Gas Town uses git-backed hooks to persist each agent's work state so restarts don't lose context, and layers on a full mechanism — a "Mayor" coordinator, "convoys" as work units, and three-tier health monitoring — for reliable orchestration, even including a merge queue and a federated cross-machine work-sharing network. It's a serious attempt to engineer the "agent fleet."

## 6. OthmanAdi/planning-with-files

⭐ 24.8k（今日 +66）· Python · [链接](https://github.com/OthmanAdi/planning-with-files)

**是什么**：为 AI 编码 Agent 和长时任务提供的「基于文件的持久化规划」方法与工具。

**What it is**: Persistent file-based planning for AI coding agents and long-running agentic tasks.

**为什么值得关注**：长任务里 Agent 最大的问题是上下文窗口一满、计划就丢。这个项目把「计划」显式落到磁盘文件上，让 Agent 在多轮、跨会话中持续读取、更新自己的待办与进度，是一种简单却好用的上下文工程范式，正被越来越多 Agent 工作流采纳。

**Why it matters**: In long tasks, an agent's biggest failure mode is losing its plan the moment the context window fills. This project makes the "plan" an explicit file on disk, letting agents continuously read and update their to-dos and progress across many turns and sessions — a simple but effective context-engineering pattern that a growing number of agent workflows are adopting.
