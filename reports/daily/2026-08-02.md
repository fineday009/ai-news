## 1. microsoft/TRELLIS.2

⭐ 9.9k（今日 +107）· Python · [链接](https://github.com/microsoft/TRELLIS.2)

**是什么**：微软研究院推出的图生 3D 生成模型，主打「原生、紧凑的结构化隐变量」（Structured Latents），约 40 亿参数，权重已上 Hugging Face，附带训练代码与网页 Demo。

**What it is**: A Microsoft Research image-to-3D generative model built on "Native and Compact Structured Latents for 3D Generation" — a ~4B-parameter model with released weights on Hugging Face, full training code, and web demos.

**为什么值得关注**：3D 生成一直卡在表征效率上，TRELLIS 系列用结构化隐变量把几何和纹理压得更紧，二代进一步把质量和可用性拉高。对做游戏资产、数字孪生、AIGC 管线的人来说，这是少见的「开源 + 权重 + 可训练」全套开放的高质量方案。

**Why it matters**: 3D generation has long been bottlenecked by representation efficiency; the TRELLIS line compresses geometry and texture with structured latents, and v2 pushes quality and usability further. For game-asset, digital-twin, and AIGC pipeline builders, a fully open stack — code plus weights plus a trainable pipeline — at this quality is rare.

## 2. bytedance/deer-flow

⭐ 78.8k（今日 +209）· Python · [链接](https://github.com/bytedance/deer-flow)

**是什么**：字节跳动开源的长时程「超级 Agent」运行时，基于 LangGraph，让 Agent 在沙箱环境里研究、写代码、创作，内置技能系统、按会话隔离的执行环境、跨会话记忆、子 Agent 委派，以及 Telegram/Slack/飞书/微信等 IM 通道接入。

**What it is**: ByteDance's open-source long-horizon "SuperAgent" harness built on LangGraph, letting agents research, code, and create inside sandboxed environments — with a skills system, per-conversation isolated execution, cross-session memory, sub-agent delegation, and IM channels (Telegram, Slack, Feishu, WeChat, and more).

**为什么值得关注**：它把「Agent 不只是带工具的聊天机器人」这句话落成了完整工程：真实的计算环境、可观测性（LangSmith/Langfuse）、多后端记忆。近 8 万星说明它已是开源 Agent 框架里的重量级选手，适合想自建长任务 Agent 平台的团队。

**Why it matters**: It turns "an agent is more than a chatbot with tools" into full engineering: real compute environments, observability (LangSmith/Langfuse), and multi-backend memory. Nearly 80k stars mark it as a heavyweight among open agent frameworks — a strong base for teams building their own long-task agent platform.

## 3. TencentCloud/TencentDB-Agent-Memory

⭐ 10.3k（今日 +227）· TypeScript · [链接](https://github.com/TencentCloud/TencentDB-Agent-Memory)

**是什么**：腾讯云开源的团队级 AI Agent「记忆中枢」，把对话、文档和代码沉淀成四类可复用资产——对话记忆（L0 原始到 L3 人格的分层蒸馏）、可执行技能、带链接图的 Wiki、以及代码调用图（CodeGraph）。

**What it is**: A team-level memory hub for AI agents from Tencent Cloud that distills conversations, docs, and code into four reusable assets — Chat Memory (layered L0-raw to L3-persona), executable Skills, a linked Wiki, and a CodeGraph of symbols and call relationships.

**为什么值得关注**：多 Agent 系统最大的浪费是重复劳动和知识流失。它不存原始日志，而是自动提炼可复用资产，并用「记忆装配（loadout）」把特定资产绑定到特定 Agent，让新 Agent 冷启动即继承团队经验。这是把「Agent 记忆」从玩具推向企业级治理的一次认真尝试。

**Why it matters**: The biggest waste in multi-agent systems is repeated work and knowledge loss. Rather than storing raw logs, it auto-extracts reusable assets and uses memory "loadouts" to bind specific assets to specific agents, so a cold-starting agent inherits team experience. It's a serious push to move "agent memory" from toy to enterprise-grade governance.

## 4. sqliteai/waste

⭐ 695 · C · [链接](https://github.com/sqliteai/waste)（2026-07-28 新建）

**是什么**：一个无依赖、可嵌入的 C 语言推理引擎，通过从 NVMe 硬盘直接流式加载被激活的权重，让 2.78 万亿参数的完整 Kimi K3 模型在超出可用内存的机器上也能跑起来。

**What it is**: A dependency-free, embeddable C inference engine that runs the full 2.78-trillion-parameter Kimi K3 model beyond available RAM by streaming activated weights directly from NVMe.

**为什么值得关注**：当前旗舰模型动辄数万亿参数，内存墙把绝大多数人挡在门外。它另辟蹊径，用「按需从磁盘流式加载激活权重」绕开显存/内存限制，把「在个人机器上跑万亿级模型」变成可能。零依赖的纯 C 实现也让它极易嵌入其他项目。

**Why it matters**: Frontier models now run to trillions of parameters, and the memory wall shuts most people out. This project sidesteps it by streaming only the activated weights from disk on demand — making trillion-parameter inference on a personal machine feasible. The zero-dependency pure-C design also makes it trivial to embed elsewhere.

**Why it matters**: Most local-model tooling on Apple Silicon is a CLI or a web wrapper; nativ delivers a cohesive native-Swift desktop experience that folds chatting, serving, and monitoring into one app. It's a friendly path for anyone who wants to run MLX models privately on a Mac without wrestling with the terminal.

## 6. github/gh-stack

⭐ 835（今日 +46）· Go · [链接](https://github.com/github/gh-stack)

**是什么**：GitHub 官方出品的 CLI 扩展，用于管理「堆叠式分支与 PR」——把一个大改动拆成一串相互依赖、各自可评审的小 PR。

**What it is**: An official GitHub CLI extension for managing stacked branches and pull requests — breaking one large change into a chain of smaller, interdependent, individually reviewable PRs.

**为什么值得关注**：堆叠 PR 一直是重度贡献者的效率利器，但手动维护 rebase 关系、base 分支和栈内导航极其繁琐。GitHub 官方下场把这套工作流自动化，还内置了可供 AI Agent 调用的 skill，意味着堆叠 PR 有望从「大厂内部工具」走向大众工作流。

**Why it matters**: Stacked PRs are a productivity multiplier for heavy contributors, but maintaining rebase relationships, base branches, and in-stack navigation by hand is tedious. GitHub itself automating the workflow — and shipping an AI-agent-callable skill with it — could move stacked PRs from big-company internal tooling into everyday practice.

## 7. trycompai/crm

⭐ 752 · TypeScript · [链接](https://github.com/trycompai/crm)（2026-07-31 新建）

**是什么**：一个「Agent 优先」的开源 CRM，理念是「Agent 不是 CRM 的一个功能，CRM 才是 Agent 记笔记的地方」。一个常驻研究型 Agent 按自己的节奏运行，自动调研联系人和公司、补全数据、安排跟进。

**What it is**: An agentic-first open-source CRM whose premise is "the agent is not a feature of the CRM; the CRM is where the agent keeps its notes." A durable research agent runs on its own schedule, autonomously researching contacts and companies, enriching data, and scheduling follow-ups.

**为什么值得关注**：它把 AI 和 CRM 的主从关系彻底倒置——不是给传统数据库加个 AI 助手，而是让 Agent 成为核心、CRM 成为它的记忆载体。「只记录观察到的事实、不做置信度打分」的设计（因为「一个自信的错误事实比一个空字段更糟」）也体现了对 Agent 幻觉的克制。

**Why it matters**: It fully inverts the AI-CRM relationship — instead of bolting an assistant onto a database, the agent is the core and the CRM is its memory. Its "record only observed facts, no confidence scoring" design — because "a confidently wrong fact is worse than a blank field" — shows disciplined restraint about agent hallucination.

## 10. xikhar/persona

⭐ 768 · JavaScript · [链接](https://github.com/xikhar/persona)（2026-07-28 新建）

**是什么**：一个桌面端的「实时角色形象」应用——捕捉系统正在播放的语音输出，用一个会动的角色形象把语音活动可视化。它明确声明不运行模型、不采集麦克风、不联网发送音频。

**What it is**: A desktop "real-time character presence" app — it captures the voice output your system is playing and visualizes that activity with an animated character. It explicitly states it does not run models, capture the microphone, or send audio over the network.

**为什么值得关注**：随着语音 Agent 兴起，「给声音一个脸」成了新需求。persona 不碰模型、只做纯本地可视化，隐私边界清晰，是给任意语音应用（不管是 LLM 还是语音助手）叠加视觉人格的轻量方案。

**Why it matters**: As voice agents rise, "giving the voice a face" becomes a new need. persona touches no model and does purely local visualization with a clear privacy boundary — a lightweight way to layer a visual persona onto any voice app, whether an LLM or a voice assistant.

### 播客要点 / Podcast

**Unsupervised Learning · Ep 92：xAI 联合创始人 Igor Babushkin 谈模型开发的未来**

嘉宾 Igor Babushkin 曾在 DeepMind 主导 StarCraft 与 AlphaCode、在 OpenAI 参与早期推理研究、是 xAI 联合创始人，如今创办 River AI。核心观点：

- **闭源模型公司正被「两头挤」**：模型太强可能因监管而不允许发布，而开源模型每个月都在逼近——他直言「你把模型做得太好，就不被允许发布；但开源就在你身后，每个月都变得更好……这其实不是身为闭源模型厂商的好位置」。出路只有持续创新。
- **River AI 押注两件事**：一是 RL + 微调服务（类似 Thinking Machines 的 Tinker，但以工程能力见长，把训练做得更便宜、可靠、可扩展）；二是「个人化 AI」——把 Agent 与个体深度对齐，甚至以「最大化用户的幸福/福祉」作为端到端训练的奖励函数。
- **美国需要世界最强的开源模型**（而非仅仅是最强的美国开源模型）；他从第一性原理认为预训练 checkpoint 理应免费开放给大家使用。
- **进一步进步的最大瓶颈**是训练方式的新思路，以及把封存在各类组织内部、尚未喂进模型的专业知识调动出来；物理世界的突破还卡在需要真实实验来闭环数据。

Guest Igor Babushkin — who led StarCraft/AlphaCode work at DeepMind, did early reasoning research at OpenAI, co-founded xAI, and now runs River AI — makes several sharp points: proprietary model builders are getting "squeezed" (too-capable models may be blocked by regulation while open models close in monthly — "you make the model too good, you're not allowed to release it, but open source is right behind you"); River AI bets on an RL/fine-tuning service (à la Thinking Machines' Tinker, differentiated by engineering) and on personal AI aligned end-to-end to an individual's "happiness"; the US needs the best open model in the world, and pre-trained checkpoints should philosophically be free; and the biggest unlock ahead is new training ideas plus surfacing expertise still locked inside organizations.
🔗 https://www.youtube.com/@RedpointAI
