**为什么值得关注**：今日 +2,050 星，日榜涨星第二。它瞄准的是"Agent 做数据分析时数字算错"这个可靠性瓶颈：从企业元数据自动生成本体、调和不同系统里互相矛盾的指标定义，用经过认证的定义和血缘校验 Agent 生成的查询，每个答案都附带出处，并通过 MCP、CLI 和 API 暴露给任意 Agent harness；被纠正的结果还会回流进本体。适合在企业数据上做 text-to-SQL 与智能分析的团队。

**Why it matters**: +2,050 stars today, second on the daily chart. ## 2. FareedKhan-dev/kimi-k3-in-c

⭐ 10,380（今日 +351）· C · [链接](https://github.com/FareedKhan-dev/kimi-k3-in-c)

**是什么**：用可移植 C99 实现的 Kimi K3 推理：2.78 万亿参数模型，单 CPU、8.24 GB 内存即可运行；不依赖 BLAS、框架和 GPU。

**What it is**: A 2.78-trillion-parameter Kimi K3 running inference on a single CPU in 8.24 GB of RAM. Portable C99: no BLAS, no framework, no GPU.

**为什么值得关注**：整个引擎只有 176 KB。1.56 TB 的权重里，1.45 TB 的路由专家从不常驻内存，而是每一步按需从磁盘流式读取并直接相乘（每 token 从 896 个专家里挑 16 个），稠密主干按可用内存决定驻留深度。代价是速度：8 GB 笔记本约 26.5 秒/token，128 GB 以上工作站约 5.6 秒/token，但不同机器输出逐字节一致。它不是生产推理方案，却是理解超大 MoE 内存结构最直观的教材。

**Why it matters**: The whole engine is 176 KB. Of the 1.56 TB checkpoint, the 1.45 TB of routed experts are never resident—they're streamed off disk and multiplied directly each step (16 of 896 experts per token)—while the dense trunk stays in memory to whatever depth RAM allows. The cost is speed: about 26.5 s/token on an 8 GB laptop and 5.6 s/token on a 128 GB+ workstation, with byte-identical output across machines. Not a production serving stack, but the most tangible lesson in how a giant MoE's memory actually works.

## 3. KKKKhazix/agent-autoloop

⭐ 2,674 · TypeScript · 创建于 2026-11-03 · [链接](https://github.com/KKKKhazix/agent-autoloop)

**是什么**：让你的命令行 Agent 在后台自己接活、自己跟进到底；平时不烦你，遇到拿不准的事才发卡片找你拍板。

**What it is**: Lets your command-line agent pick up work in the background and follow it through on its own—staying quiet until something needs your call, then sending you a card. (Translated from Chinese.)

**为什么值得关注**：上线两天近 2.7k 星。它把 Claude Code、Codex 这类"人守着终端用"的 Agent 变成后台常驻的同事：内核约 1800 行、零运行时依赖，事件源、Agent、通知通道（飞书、钉钉、企微、Slack、Discord）都是插件，能接收提示词并打印回复的 CLI 一行配置就能接。设计上很讲究——等你拍板时进程直接退出、不耗 token；状态全部来自只追加日志；Issue 等外部文字只当资料不拼进提示词，防注入；Agent 互相派活超过 8 层自动熔断。目前支持 macOS 与 Linux。

**Why it matters**: Nearly 2.7k stars in two days. It turns "babysat-in-a-terminal" agents like Claude Code and Codex into background teammates: a ~1,800-line kernel with zero runtime dependencies, with event sources, agents and notification channels (Feishu, DingTalk, WeCom, Slack, Discord) as plugins, and any CLI that takes a prompt and prints a reply wired in with one line of config. The design is careful—processes exit while waiting for you, so no tokens burn; all state is derived from an append-only log; external text like issue bodies is passed as data, never spliced into prompts, to resist injection; and agent-to-agent hand-offs trip a breaker after 8 hops. macOS and Linux for now.

- **A software-first cloud**: Nebius sees itself as a software company built on solid hardware, not a managed bare-metal provider; a hardware team from Yandex with experience running servers at massive scale was key to early build-outs.
- **Racks, not servers**: Products like Grace Blackwell are sold only at rack level, and maintenance shifts from switching off one server to servicing a whole rack; some customers routinely pull around 700 GB/s from a single shared file system.
- **Customers run modified models**: about 95% of customers don't run vanilla open-source models but fine-tuned, domain-scoped versions.
- **The one bottleneck is execution**: GPUs, CPUs, NVMe and even transformers (with lead times in years) are all scarce; hyperscalers are constrained by chip allocation, which is the window for neoclouds. Next, he's most interested in outcome optimization for long-running agents.
