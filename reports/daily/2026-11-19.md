## 1. HKUDS/CLI-Anything

⭐ 59.9k（今日 +389）· Python · [链接](https://github.com/HKUDS/CLI-Anything)

**是什么**：「CLI-Anything：让所有软件都成为 Agent 原生」——用一条命令为现有软件生成一套 CLI，让 Pi、OpenClaw、nanobot、Cursor、Claude Code 等 Agent 都能直接驱动它；配套 CLI-Hub 用来浏览和安装社区构建的 CLI。

**What it is**: "CLI-Anything: Making ALL Software Agent-Native"—one command line generates a CLI for existing software so agents such as Pi, OpenClaw, nanobot, Cursor and Claude Code can drive it, with CLI-Hub (`pip install cli-anything-hub`) for browsing and installing community-built CLIs.

**为什么值得关注**：它押注"CLI 是人与 Agent 共同的通用接口"：文本命令天然贴合 LLM、可组合、`--help` 自描述、输出结构化 JSON。以 GIMP 为例，`/cli-anything` 分 7 个阶段生成完整 CLI，之后可反复用 `refine` 做能力差距分析、补齐命令、测试和文档；每个生成的 CLI 还自带 SKILL.md 供 Agent 发现。社区已合入 QGIS、Shotcut、UniMol 等 harness，适合想让 Agent 操作桌面/专业软件、又不想写 GUI 自动化的人。

**Why it matters**: It bets that the CLI is the universal interface for both humans and agents: text commands match how LLMs work, compose well, self-document through `--help` and return structured JSON. Taking GIMP as the example, `/cli-anything` builds a complete CLI in 7 phases, and `refine` can then be run repeatedly to analyze capability gaps and add commands, tests and docs; every generated CLI ships with a SKILL.md so agents can discover it. The community has merged harnesses for QGIS, Shotcut, UniMol and more—useful if you want agents to operate desktop or professional software without writing GUI automation.

## 10. adriadam10/mkw-recomp

⭐ 1,507 · C · 创建于 2026-11-09 · [链接](https://github.com/adriadam10/mkw-recomp)

**是什么**：将《马力欧赛车 世界》（Nintendo Switch 2）静态重编译为可在 Linux 和 Windows 原生运行的 PC 程序。

**What it is**: Static recompilation of Mario Kart World (Nintendo Switch 2) to a native PC program for Linux and Windows.

**为什么值得关注**：这是重编译而非模拟器：游戏的 AArch64 代码被提前翻译成 C 再编译，没有解释器或 JIT；Switch 2 图形 API NVN2 在 API 层用 Vulkan 重新实现，SM86 着色器提前转成 SPIR-V。截至 11 月 12 日已能完整走完片头、菜单与比赛，高端 GPU 上 60 fps，并有 Linux AArch64 版本；仓库不含任何游戏内容，需要玩家自己从主机中提取。路线图把渲染录制的 CPU 开销列为下一步重点，是近期 Switch 2 静态重编译热潮中技术细节最透明的一个。

**Why it matters**: It's a recompilation, not an emulator: the game's AArch64 code is translated to C ahead of time and compiled, with no interpreter or JIT; NVN2, the Switch 2 graphics API, is reimplemented on Vulkan at the API level, and SM86 shaders are translated to SPIR-V ahead of time. As of November 12 it boots through intro movies, menus and races, runs at 60 fps on high-end GPUs and has a Linux AArch64 build; nothing of the game is in the repo, so you need your own dump. The roadmap targets the CPU cost of Vulkan command recording next—one of the most transparent write-ups in the recent wave of Switch 2 static recompilations.

**一句话**：Black Forest Labs 从来不想只做一家图像生成公司——图像是通往"视频理解世界、再到机器人"的一段成功弯路。

**The takeaway**: Black Forest Labs was never meant to be just an image lab—images were a successful detour on the way to video as a model of the world, and then robotics.

- **嘉宾**：Andreas Blattmann 是潜在扩散（latent diffusion，Stable Diffusion 的底层技术）的共同发明人、BFL 联合创始人；Dustin Podell 当了约 10 年软件开发者后转入生成模型，主导过 SDXL、SD3 后训练和 Flux 系列。
- **Guests**: Andreas Blattmann co-invented latent diffusion (the technique behind Stable Diffusion) and co-founded BFL; Dustin Podell spent about 10 years as a software developer before moving into generative models, working on SDXL, SD3 post-training and the Flux line.
- **为何离开 Stability**：他们看到自家模型撑起了大量开源项目和公司，但 Stability 自己没能把模型价值变现；BFL 就是"纠正这个错误"的机会。据称至今融资约 4.5 亿美元，12 月公布的收入为 1 亿美元。
- **Why they left Stability**: Their models powered a huge open-source scene and many companies, yet Stability couldn't capture that value; BFL was their shot at correcting it. They say they've raised about $450M so far, with $100M in revenue as last published in December.
- **Flux Kontext 的起点**：一个只描述图中简单空间关系的小型高质量数据集，训练了大约四到六个小时，就"突然看到了明确的泛化"——能把 logo 放到衬衫上。动机是大家为了角色一致性训练了无数 LoRA，可控性才是要解决的核心问题。
- **How Flux Kontext started**: A tiny, high-quality dataset that just described simple spatial relationships in images, trained for maybe four to six hours—and "all of a sudden… a clear generality" emerged, like putting a logo on a shirt. The motivation: people were training endless LoRAs just for character consistency; controllability is the real problem.
- **机器人方向**：他们的机器人模型在一个工业场景中只用约 4 小时数据就达到可用成功率，称比一个开源对照模型少用 8 倍数据；但真正目标是不做微调、靠上下文学习——"给机器人看一次动作，它就该会做"。
- **Robotics**: Their robotics model reached a good-enough success rate on an industrial task with about 4 hours of data, which they say is 8× less than an open-source baseline—but the real goal is no fine-tuning at all, via in-context learning—a robot should be able to watch an action once and then do it.
