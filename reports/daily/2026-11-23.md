## 1. huggingface/pybot

⭐ 1,120 · Python · 创建于 2026-11-12 · [链接](https://github.com/huggingface/pybot)

**是什么**：PyBot——由一群 Agent 用纯 Python 写出来的聊天机器人。没有权重，没有训练，只有规则。

**What it is**: PyBot: a chatbot written in pure Python by a swarm of agents. No weights, no training, just rules.

**为什么值得关注**：这是一个很反直觉的实验：60 年前的 ELIZA 靠模式匹配和模板对话，扩展能力只能靠人手写规则；如果让 Agent 群来写呢？Hugging Face 让 1,000 多个 Agent 只用 if-else、正则和查找表构建聊天机器人，写出并评估了 5,000 多个版本，在 SmolTalkBench 上的胜率从 0% 爬到 26%，README 称与 SmolLM-360M-Instruct 相当。成品约 64 万行代码，外加 Agent 自己写的 55 万行测试，只需 Python 3.8+、无任何依赖和模型下载。它的实用价值有限，但作为"Agent 群能把一件纯体力活推到多远"的公开样本很有参考意义。

**Why it matters**: A counterintuitive experiment: sixty years ago ELIZA held conversations with pattern matching and templates, and extending it meant hand-writing more rules—so what if a swarm of agents did that work instead? Hugging Face had over 1,000 agents build a chatbot from nothing but if-else branches, regex patterns and lookup tables; they wrote and evaluated over 5,000 versions, and its win rate on SmolTalkBench climbed from 0% to 26%, which the README puts on par with SmolLM-360M-Instruct. The result is around 640k lines of code backed by 550k lines of tests the agents wrote themselves, needing only Python 3.8+ with no packages and no model download. Its practical use is limited, but as a public sample of how far an agent swarm can push pure grunt work, it's a useful reference.

## 2. EL4CTEO/fast-anything

⭐ 2,047 · Rust · 创建于 2026-11-21 · [链接](https://github.com/EL4CTEO/fast-anything)

**是什么**：别用 Rust 重写整个项目，只重写慢的那 5%：对 Python、Node 或 Ruby 应用做性能分析，让你的编码 Agent 移植热点函数，并证明行为一致。

**What it is**: Don't rewrite it in Rust. Rewrite the 5% that's slow: profile Python, Node or Ruby apps, port the hot functions with your coding agent, prove they behave the same.

**为什么值得关注**：创建两天即过 2,000 星，明显是对上周走红的 rust-anything（整体迁移到 Rust）的反向回应。流程是 `scan` 分析并按"耗时 × 可移植性"给函数排序，`port` 录制最多 500 次真实调用并生成单函数 Rust crate 和 `TASK.md`，`verify` 用 release 构建回放每一次调用，`enable`/`disable` 以一个带标记的代码块换入换出。它强调"要证据不要感觉"：除录制的调用外还会派生 NaN、±无穷、非 ASCII 文本、空输入等边界用例，全部匹配才启用；移植正确但单次调用更慢的也不启用。`--agent` 支持 claude、codex 或任何从 stdin 读提示词的命令。适合有明确热点、但不想为性能付出整体重写代价的团队。

**Why it matters**: Past 2,000 stars two days after creation, and clearly a counter-move to last week's rust-anything (migrate the whole app to Rust). The flow: `scan` profiles the app and ranks functions by time × portability, `port` records up to 500 real calls and creates a one-function Rust crate plus a `TASK.md`, `verify` release-builds the port and replays every recorded call, and `enable`/`disable` swaps it in or out as one marked block. Its pitch is proof, not vibes: on top of the recorded calls it derives edge cases (NaN, ±infinity, non-ASCII text, empty inputs and more), and nothing is enabled until every case matches—a port that is correct but slower per call isn't enabled either. `--agent` takes claude, codex, or any command that reads a prompt on stdin. A fit for teams with clear hot spots who don't want to pay for a full rewrite.

## 3. pithings/unkernel

⭐ 1,152 · TypeScript · 创建于 2026-11-12 · [链接](https://github.com/pithings/unkernel)

**是什么**：一个真正的 Linux 内核，编译成 WebAssembly，不到一秒就能启动到 shell。

**What it is**: A real Linux kernel, compiled to WebAssembly. It boots to a shell in less than a second.

**为什么值得关注**：它把 Linux 7.x 构建成带真实 MMU 的单个 wasm 模块：内核（系统调用、调度器、内存管理、ext4、TCP/IP）是编译后的代码而非模拟，被模拟的只有用户态程序——未经修改的 aarch64 Linux 二进制，所以 Alpine 和 Debian 的软件包可以原样运行。打开一个网页就有一台带 shell、包管理器、持久化磁盘、联网和带声音屏幕的 Linux 机器，完全在本机运行。README 给出的数据：内核启动约 70 毫秒到达 `/init`，页面下载约 10 MB，`getppid` 约 170 纳秒（原生 110），fork + exit + wait 约 60 微秒；CPU 密集型程序则明显慢于原生。对想在浏览器里给用户或 Agent 一个真实 Linux 环境的人值得关注。

**Why it matters**: It builds Linux 7.x as a single wasm module with a real MMU: the kernel (syscalls, scheduler, memory management, ext4, TCP/IP) is compiled code rather than emulated, and only user programs are emulated—unmodified aarch64 Linux binaries, so Alpine and Debian packages run as they are. Open a page and you have a Linux machine with a shell, a package manager, a persistent disk, internet access and a screen with sound, running entirely on your device. The README's numbers: the kernel reaches `/init` about 70 ms after it starts, the page downloads about 10 MB, `getppid` takes about 170 ns (110 native) and fork + exit + wait about 60 µs; CPU-heavy programs are well behind native. Worth watching if you want to hand users or agents a real Linux environment inside a browser.

A fit for players who want frame generation on older or non-NVIDIA cards, and for anyone who needs an objective comparison across vendors.

**是什么**：Leonida 是 Xbox 版《侠盗猎车手 6》的原生 PC 重编译项目。

**What it is**: Leonida is a native PC recompilation of the Xbox version of Grand Theft Auto 6.

**为什么值得关注**：创建三天就有约 1.6 万星，是近两周新建仓库里星数最高的。但请先看清现状：README 明确写着"还很早期，游戏目前无法启动"，没有任何可玩内容。它是一个静态重编译项目——Xbox Series 的 CPU 与 PC 同为 x86-64，所以游戏代码原生加载运行、主机系统软件被重新实现，主机预编译的 RDNA2 GPU 程序被翻译成 SPIR-V 交给 Vulkan。目前真正完成的是着色器这一段：README 称全部 26,503 个着色器已完成翻译并通过 `spirv-val` 校验。仓库不含游戏、密钥或可执行文件，也不解释如何获取，需要你自己的游戏拷贝。把它当作一次公开进行的大型逆向工程来围观比较合适，而不是可以下载的 PC 版。

**Why it matters**: About 16k stars three days after creation—the most-starred repo created in the past two weeks. But read the status first: the README says plainly that it's early and the game does not boot yet, with nothing playable. It's a static recompilation project: the Xbox Series CPU is x86-64 like a PC, so the game's code is loaded and run natively while the console's system software is reimplemented, and the console's precompiled RDNA2 GPU programs are translated to SPIR-V for Vulkan. What's actually done so far is the shader side: the README reports all 26,503 shaders translated and passing `spirv-val`. The repository contains no game, keys or executable and doesn't explain how to get them; you need your own copy. Best treated as a large reverse-engineering effort happening in public, not as a PC version you can download.
