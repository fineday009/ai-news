## 1. vercel-labs/agent-desktop

⭐ 22.4k（本周 +7,772）· Rust · [链接](https://github.com/vercel-labs/agent-desktop)

**是什么**：面向 AI Agent 的 computer use：通过操作系统无障碍树查看并操作 macOS、Windows 和 Linux 上的桌面应用。

**What it is**: Computer use for AI agents: see and operate desktop apps on macOS, Windows, and Linux through the OS accessibility tree.

**为什么值得关注**：11 月 3 日以 10.2k 星登上日报榜首，九天后已到 22.4k，本周仍以 +7.7k 位居周榜前列。它不靠截图和像素匹配，而是把应用的无障碍树读成 JSON、给每个可操作元素一个 ref，Agent 点击或输入后再读一次 UI 来验证；ref 绑定到具体快照，界面变化时返回 `STALE_REF` 要求重新观察，默认无头操作、不抢鼠标焦点。工具本身不含模型，以 CLI 和 C 库形式发布，适合想给自家 Agent 加桌面操作能力的开发者。

**Why it matters**: It topped the daily on November 3 at 10.2k stars and is at 22.4k nine days later, still near the top of the weekly chart at +7.7k. Instead of screenshots and pixel matching, it reads an app's accessibility tree as JSON with a ref for every actionable element; the agent clicks or types on a ref, then reads the UI again to verify. Refs belong to a specific snapshot, so a changed UI returns `STALE_REF` and forces a fresh look, and actions are headless by default without moving the pointer or stealing focus. There's no model inside—it ships as a CLI and a C library—making it a good fit for developers adding desktop control to their own agents.

## 2. herdrdev/herdr

⭐ 50.5k（本周 +2,213）· Rust · [链接](https://github.com/herdrdev/herdr)

**是什么**：你的编码 Agent 赖以运行的运行时。

**What it is**: The runtime your coding agents live on.

**为什么值得关注**：它不包装也不替代 Claude Code、Codex、Cursor、opencode 等 Agent，而是接管它们所在的终端：客户端关掉或 SSH 断线后终端仍在后台服务器里跑，重启后恢复布局并可续接支持的 Agent 会话；本地与多台 SSH 机器汇到一个窗口，每个窗格标注"工作中 / 卡住 / 空闲"，Agent 停下等回答时会提醒你。Agent 还能通过 CLI 和 socket API 自己开窗格、互相发提示、等待另一个 Agent 真正卡住。单个 Rust 二进制、无 Electron，兼容 tmux 式前缀键和鼠标操作，适合同时开多个 Agent 的重度用户。

**Why it matters**: It doesn't wrap or replace Claude Code, Codex, Cursor, opencode and the rest—it owns their terminals. Terminals keep running in a background server when you close the client or lose SSH; after a restart it restores the layout and can resume supported agent sessions. Local work and saved SSH machines share one window, every pane is marked working, blocked or idle, and herdr tells you when an agent stops and needs an answer. Agents can also drive it through the CLI and socket API to spawn panes, prompt each other and wait until another agent is genuinely blocked. One Rust binary, no Electron, with tmux-style prefix keys and first-class mouse support—built for people running many agents at once.

## 3. shadcn/improve

⭐ 11.2k（今日 +361）· [链接](https://github.com/shadcn/improve)

**是什么**：一个 Agent skill：用你最强的模型审计代码库、写出实现计划，再交给更便宜的模型去执行。

**What it is**: Use your most capable model to audit your codebase and write plans for cheaper models to execute.

**为什么值得关注**：出自 shadcn/ui 作者，核心观点是"计划才是产品"：贵模型只负责理解代码库、判断什么值得做、写出自包含的规格，自己从不动手实现。`/improve` 输出带类别、工作量和置信度的发现表，选中的条目在 `plans/` 下生成独立计划（附现有代码摘录、具体步骤、仓库自己的测试/lint 命令作为验收关口和停止条件）；`/improve execute` 会在隔离 worktree 里派便宜模型执行并按计划审查 diff，`reconcile` 负责清理积压。被否决的发现会记录理由，下次不再重提。对想控制 token 成本又不想牺牲质量的团队，这是一套很清晰的分工模式。

**Why it matters**: From the creator of shadcn/ui, its core idea is "the plan is the product": the expensive model only understands the codebase, judges what's worth doing and writes self-contained specs—it never implements anything itself. `/improve` returns a findings table with category, effort and confidence; picked items become standalone plans in `plans/` with current code excerpts, exact steps, the repo's own test/lint commands as verification gates, and stop conditions. `/improve execute` dispatches a cheaper model in an isolated worktree and reviews the diff against the plan, and `reconcile` cleans up the backlog. Rejected findings are recorded with reasons so they don't come back. For teams that want to cut token costs without cutting quality, it's a clean division of labor.

## 4. storytold/craft-anything

⭐ 29.0k · Rust · 创建于 2026-10-31 · [链接](https://github.com/storytold/craft-anything)

**是什么**：看懂任何网站、应用或游戏是怎么工作的，再让 AI 做出你自己的版本；一个纯 Rust 的开源洁净室（clean-room）引擎。

**What it is**: See how any website, app or game works, then have AI build your own version; an open-source, clean-room engine in pure Rust.

**为什么值得关注**：11 月 3 日上日报时约 4.7k 星，如今已到 29.0k，是本周新项目涨星最快的之一。它把"用真实检查工具研究原作 → 编码 Agent 构建新项目 → 与原作比对 → 迭代"做成固定流水线，每次检查都给出相似度和未对齐清单，超出规则的命令需要你审批。出自推出 photocraft、pdfcraft、wordcraft 等纯 Rust 套件的 ArtCraft 团队，覆盖 macOS、Windows、Linux、FreeBSD 和 Web，目前仍是 early alpha。

**Why it matters**: It had about 4.7k stars when it made the daily on November 3 and has 29.0k now, one of this week's fastest-growing new repos. It turns "study the original with real inspection tools → have a coding agent build a new project → check it against the original → refine" into a fixed pipeline; each check reports how alike the build is and what still doesn't match, and anything outside the rules waits for your approval. It comes from the ArtCraft team behind the pure-Rust photocraft, pdfcraft and wordcraft suites, runs on macOS, Windows, Linux, FreeBSD and the web, and is still early alpha.

## 5. DIYgod/pinky

⭐ 1.9k · Go · 创建于 2026-11-06 · [链接](https://github.com/DIYgod/pinky)

**是什么**：让任何 AI Agent 从 macOS、Windows 或 Linux 上操作你的 iPhone 或 Android 手机，全程有你把关。

**What it is**: Let any AI agent use your iPhone or Android phone, from macOS, Windows or Linux, with you in the loop.

**为什么值得关注**：Claude Code、Codex、Cursor 等任何支持 MCP 的 Agent 都能通过它操作真机，你在电脑上旁观、审批、随时接管和回看。关键在于审批规则跑在 Pinky 的网关里而非写给 Agent 的提示：付款、交易、转账默认等你点击，发送、下单、删除等也可设为需审批，Agent 无法自己批准自己，屏幕上的文字诱导也没用；银行、钱包、密码管理器应用默认对 Agent 不可见，Agent 也不能在密码或验证码框里输入。原生 GPU 绘制界面、无 Electron，安装包 16–22 MB，Apache-2.0。

**Why it matters**: Any MCP-capable agent—Claude Code, Codex, Cursor and more—can operate a real phone through it while you watch on your computer, approve risky steps, take over and review what happened. The key design choice is that approvals are enforced in Pinky's gateway, not in instructions to the agent: payments, trades and transfers wait for your click by default, sends, orders and deletions can be made to wait too, and an agent can't approve itself even if on-screen text tries to talk it into it. Banking, wallet and password-manager apps are invisible to agents by default, and agents can't type into password or one-time-code fields. A native GPU-drawn UI with no Electron, a 16–22 MB download, Apache-2.0.

## 6. openai/codex-security

⭐ 12.0k（今日 +52）· TypeScript · [链接](https://github.com/openai/codex-security)

**是什么**：OpenAI 的 Codex Security CLI 与 TypeScript SDK，用于发现、验证并修复代码中的安全漏洞。

**What it is**: OpenAI's Codex Security CLI and TypeScript SDK for finding, validating, and fixing security vulnerabilities.

**为什么值得关注**：OpenAI 官方的 AI 安全审计工具链，可在 Codex 里直接用，也可通过 `cs scan` 命令行、TypeScript SDK 或 GitHub Action 接入 CI。它支持扫描整个仓库、指定路径或某个基线以来的 diff，Deep 模式重复标准扫描并去重；之后可验证候选漏洞、生成补丁、核验已有修复，起草 `SECURITY.md` 和威胁模型，并按自定义标准评估严重度、根据 Git 历史推荐负责人，结果可推到 Linear、Jira、GitHub 或导出 SARIF。和 Cloudflare 的 security-audit-skill 一样，代表"Agent 做安全审计"正在走向正式产品化。

**Why it matters**: OpenAI's official toolchain for AI security audits, usable inside Codex or wired into CI through the `cs scan` CLI, the TypeScript SDK or a GitHub Action. It scans whole repos, selected paths or the diff from a base revision, with a Deep mode that repeats standard scans and deduplicates findings. From there it validates candidates, generates patches, verifies existing fixes, drafts `SECURITY.md` policies and threat models, rates severity against your own rubric, suggests owners from Git history, and pushes results to Linear, Jira or GitHub or exports SARIF. Like Cloudflare's security-audit-skill, it shows agent-driven security review becoming a real product category.

## 8. Sandflow-ai/sand3d

⭐ 1.9k · HTML · 创建于 2026-11-03 · [链接](https://github.com/Sandflow-ai/sand3d)

**是什么**：为 LLM 打造的 Python 3D 建模库。

**What it is**: 3D modeling in Python, built for LLMs.

**为什么值得关注**：它让 3D 物体以短程序的形式描述——轮廓、实体、编辑、坐标系、关节和装配，底层基于 Blender 的 `bpy`。程序写的是形状"如何做出来"，零件和边都有名字而不是靠计算坐标，模型几百个 token 就能写完，人也读得懂。README 给出的测量是：同一零件所需 token 比 Blender Python、CadQuery 或 FeatureScript 少 2–6 倍，整个 API 约 3,600 token、可整体放进提示词；还配有 Hugging Face 数据集和在线浏览器。适合做 text-to-CAD 或让 Agent 生成可编辑 3D 资产的人。

**Why it matters**: It describes 3D objects as short programs—profiles, solids, edits, frames, joints and assemblies—on top of Blender's `bpy`. A program says how a shape is made, with named parts and edges rather than computed coordinates, so a model can write it in a few hundred tokens and a person can read it. The README measures 2–6× fewer tokens per part than Blender Python, CadQuery or FeatureScript, and the whole API fits in a prompt at about 3,600 tokens; there are Hugging Face datasets and an online explorer too. Useful for text-to-CAD work or agents that need to produce editable 3D assets.

## 9. shanselman/gputaskman

⭐ 2.2k · Python · 创建于 2026-11-03 · [链接](https://github.com/shanselman/gputaskman)

**是什么**：适用于 Windows、Linux 和 WSL 的 GPU 任务管理器：按进程显示显存、GPU 活动，以及 LLM 模型/KV cache 的占用细分。

**What it is**: A GPU task manager for Windows, Linux, and WSL: per-process VRAM, GPU activity, and LLM model/KV-cache insight—an `htop` for what's inside your GPU, not just how full it is.

**为什么值得关注**：任务管理器只告诉你"用了 15 GB"，它试图回答"被谁用了"：模型权重、KV cache、浏览器还是桌面合成器，以及为什么大量显存落在系统内存里。终端界面把按进程的显存和引擎活动与已加载的运行时、模型文件、LLM 缓冲区细分关联起来，支持 NVIDIA/AMD/Intel 和 Apple Silicon，可用 `uv tool install` 一键安装或下载 Windows 便携版。README 坦诚区分"测量值"和"估算值"，目前仍属实验性。本地跑模型的人排查显存非常实用。

**Why it matters**: Task Manager says "15 GB used"; this tries to answer by what—model weights, KV cache, your browser, the desktop compositor—and why so much GPU memory sits in system RAM. Its terminal UI ties per-process VRAM and engine activity to loaded runtimes, model files and LLM buffer breakdowns, across NVIDIA, AMD, Intel and Apple Silicon, installable with `uv tool install` or as a portable Windows ZIP. The README is careful to separate measurements from estimates, and it's still experimental. Very handy for anyone debugging VRAM while running models locally.

## 10. jamesondh/chimera-vocal-synth

⭐ 2.0k · Rust · 创建于 2026-11-05 · [链接](https://github.com/jamesondh/chimera-vocal-synth)

**是什么**：终极人声合成器——唱歌、说话、Beatbox 等等，全部来自浏览器里的物理建模。

**What it is**: The ultimate vocal synthesizer—sing, speak, beatbox, and more. A physical-modeling voice synthesizer in the browser.

**为什么值得关注**：今天榜单里最"反潮流"的项目：没有采样、没有神经网络音频，每个声音都来自模拟的气道——肺、声带（或鸟类鸣管）、分叉声道、嘴唇和鼻腔。引擎用 Rust 编写、编译成 WebAssembly 跑在 AudioWorklet 里；可以拖动舌头、嘴唇和下颌实时发声，输入英文或 IPA 让它说话，在钢琴卷帘上写歌词让它唱（支持英语和韩语），还有 Beatbox 步进音序器和鸟、海豹、鳄鱼、大象等"动物图鉴"。CLI 能把结果与真实歌手和 23 位真实说话人对比。MIT 协议，声学和音乐爱好者都值得一玩。

**Why it matters**: The most against-the-grain project on today's list: no samples and no neural audio—every sound comes from a simulated airway of lungs, vocal folds (or a bird's syrinx), a branched vocal tract, lips and nose. The Rust engine compiles to WebAssembly for an AudioWorklet. You can drag the tongue, lips and jaw to play it live, type English or IPA to make it speak, write lyrics on a pitch roll to make it sing (English or Korean), program beats on a step sequencer, or try the bestiary of songbird, seal, alligator and elephant. Its CLI compares output against a real singer and 23 real speakers. MIT-licensed and worth a play for anyone into acoustics or music.

**AI & I by Every**：[A New Vision for Human Work After Automation](https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL)

一句话结论：Every CEO Dan Shipper 在自家大会 Thesis 的闭幕演讲中提出——当每个人都拿到同样的模型，默认答案就只是底线，人的价值在于用自己的视角和责任把模型推得更远。

- 两种预测未来的方法："宏观"（大量数据外推趋势线）和"贴身"（深入一个真实案例再外推）。宏观视角很有力——OpenAI 的 GDPval 上，AI 胜过人类专家的比例从 2024 年的 12.4%、2025 年的 47.6% 升到 2026 年约 83%——但它必须把人"冻结"在过去来比较。
- 贴身视角：他在一周的日程缝隙里用 Claude 分析季度用户调查、给团队做了一个实时问答游戏、发现"卖给团队"的机会、vibe code 了一个 CRM 并开始外联——按 2020 年的标准相当于五个人、约 20 万美元。
- 但同一份调查、同一个模型，团队成员看到的完全不同：GTM 工程师 Yash 发现首月新订户因邮件太多而流失，市场负责人 Douglas 发现很多读者感到孤独（身边人觉得他们痴迷 AI 很怪），编辑 Jack 做了一档黏土动画游戏节目；而 Claude 的默认回答虽然正确，却是人人都能拿到的"廉价洞察"。
- 评测负责人 Mike Taylor 的实验：让 Claude 预测 Dan 在 Slack 里会说什么，给 400 次机会时 93% 能覆盖到；但让它自己排序，Dan 的真实回答只有约 60% 的情况落在前 10%。生成很便宜，排序很难——每个人的职责缩小了搜索范围，视角帮他排出优先级。
- "2027 年的 Claude 会排序了"不构成反驳：届时比较的是"用着 2027 Claude 的 2027 年 Yash"和"2027 Claude 的默认提示词"，两边的 Claude 可以约掉。因此他主张改变衡量 AI 的方式：不只问它在公认问题上表现如何，而要问"它从我的视角做我的工作做得怎样"——这也是他所说的"分配经济"（allocation economy）。

The takeaway: closing Every's Thesis conference, CEO Dan Shipper argues that when everyone has the same model, the default answer is just the floor—human value lies in using your own perspective and responsibility to push the model further.

- There are two ways to predict the future: the aggregate (gather lots of data, extrapolate a trend line) and the intimate (zoom in on one real case, then extrapolate). The aggregate is powerful—on OpenAI's GDPval, AI beat human experts 12.4% of the time in 2024, 47.6% in 2025 and about 83% in 2026—but it has to freeze humans in the past to make the comparison.
- The intimate view: in the cracks of one week he used Claude to analyze the quarterly customer survey, build a live game for the team, spot an opportunity to sell Every to teams, vibe-code a CRM and start outreach—roughly five people and $200K in 2020 terms.
- Yet with the same survey and the same model, teammates found very different things: go-to-market engineer Yash saw first-time subscribers churning because of too much email, marketing head Douglas found many readers feel lonely (people around them think their AI enthusiasm is crazy), and editor Jack made a Claymation game show. Claude's default answer was true, but it's a cheap insight anyone can get.
- Head of evals Mike Taylor's experiment: given 400 attempts, Claude produced something like what Dan would say in Slack 93% of the time, but when ranking its own answers, Dan's actual reply landed in the top 10% only about 60% of the time. Generation is cheap; ranking is hard. Each person's responsibility narrows where they look, and their perspective ranks what matters.
- "Claude will rank better in 2027" isn't a rebuttal: the real comparison is 2027 Yash using 2027 Claude versus 2027 Claude's default prompt—the Claudes cancel out. So he argues we should change how we measure AI: not only how it does on problems everyone agrees on, but how well it does my work from my perspective—what he calls the allocation economy.
