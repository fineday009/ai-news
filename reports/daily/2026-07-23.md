### 播客要点 / Podcast

**Training Data — Factory 创始人 Matan Grinberg：软件自我构建的"黑灯工厂"**

**核心观点**：在软件越来越能自我构建的时代，真正的护城河不是模型，而是包裹模型的 harness——以及企业围绕 token 与"产出"重构的预算与定价方式。

要点：
- **不要把命运交给单一模型厂商**。企业对云厂商锁定"人人有伤疤"（先补贴、续约时涨价 10 倍），因此 Factory 坚持模型无关。原话："We cannot put our fate in any one of these model providers' hands."
- **harness 的前沿由工程细节决定**：token 缓存（缓存 token 便宜约 10 倍）和长会话压缩/压紧（compaction）时的表现，是拉开差距的关键。
- **企业 token 预算即将成为难题**：给每个人一刀切的 token 上限没有意义；未来每个 CIO 都要为"每一份增量 token 花在哪"负责——vibe coding 仪表盘的 PM 不该和搭建关键基础设施的工程师用同一额度。
- **定价从按席位转向按产出**：一旦能拆分任务、形成 Agent 的竞争市场，用户就有动力把验收标准写得极其严谨（否则"让 Agent 修代码，它可能把你代码删了"）。

**The Takeaway**: When software increasingly builds itself, the durable moat isn't the model — it's the harness around it, and enterprises must rethink budgeting and pricing around tokens and outcomes.

Key points:
- **Don't hand your fate to a single model provider.** Everyone carries "scars" from cloud lock-in (subsidize first, 10x the contract at renewal), so Factory stays model-agnostic. In his words: "We cannot put our fate in any one of these model providers' hands."
- **A harness stays at the frontier on engineering details**: token caching (cached tokens are ~10x cheaper) and how well it performs during long-session compression/compaction.
- **Enterprise token budgeting is about to get hard**: a blanket per-person token cap makes no sense; every CIO will have to answer for "where does each incremental token go" — a PM vibe-coding dashboards shouldn't get the same allowance as an engineer building critical infra.
- **Pricing shifts from per-seat to outcome-based**: once tasks can be subdivided into a competitive marketplace of agents, users are incentivized to write rigorous validation criteria (or "you ask an agent to fix your code and it deletes your code").
