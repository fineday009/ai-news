## 6. bendlang/bend

⭐ 25.8k（今日 +50）· TypeScript · [链接](https://github.com/bendlang/bend)

**是什么**：Bend 2：一门通过证明来拦截 AI 错误的高速语言。

**What it is**: Bend 2: a fast language that blocks AI mistakes via proof.

**为什么值得关注**：今日 +50 星。它直面一个越来越现实的问题：不读代码，怎么信任 AI 写的代码？Bend 的答案是让 AI 写出正确性证明。你在 `LAWS.bend` 文件里声明应用不能违反的规则（例如"所有余额之和必须为零"），之后每次改动代码，编译器都要求数学证明这些规则仍然成立；Agent 引入违反规则的 bug 时无法通过，只能重试。README 给自己定的目标是 CPU 上与 C 一样快、GPU 上与 CUDA 一样快，并称凭借强类型、纯函数和线性类型，单核已能编译出与手写 C 同样快的可执行文件，证明检查也在一秒内完成其他项目需要几分钟的文件——这些都是项目自述，尚需独立验证。对关注形式化验证和 AI 代码可信度的人，这是值得跟踪的方向。

**Why it matters**: +50 stars today. It goes straight at an increasingly practical question: how do you trust AI-written code without reading it? Bend's answer is to make the AI write a correctness proof. You declare rules your app must not break in a `LAWS.bend` file (for example, that the sum of all balances must be zero), and whenever the code is edited the compiler demands mathematical proof that the laws still hold; an agent that introduces a law-breaking bug is blocked and has to retry. The README sets the target of being as fast as C on the CPU and as fast as CUDA on the GPU, and says that thanks to strong types, purity and linearity it already compiles to executables as fast as hand-written C on a single core, and checks in under a second files that take other projects minutes—these are the project's own claims and still need independent verification. A direction worth tracking for anyone interested in formal verification and trustworthy AI code.

## 7. ivall/xcl

⭐ 3,631 · Rust · 创建于 2026-11-20 · [链接](https://github.com/ivall/xcl)

**是什么**：面向 Windows 的 Xbox Series 兼容层——原生运行主机游戏代码，重新实现主机系统库，并把 RDNA2 着色器重编译为 DXIL。

**What it is**: Xbox Series compatibility layer for Windows - runs console game code natively, reimplements the console system libraries and recompiles RDNA2 shaders to DXIL.

**为什么值得关注**：创建四天 3,631 星。它走的是 Wine/Proton 的路线而不是模拟器：Xbox Series 的 CPU 本就是 x64，所以游戏代码不经 CPU 模拟直接在 PC 上原生运行，XCL 负责替代 PC 上没有的主机库（`kernelx.dll`、XGameRuntime、`d3d12_xs.dll` 等），并把主机的 RDNA2 GPU 机器码翻译成 HLSL 再编译为 DXIL。与近期同类项目多停留在"尚不能启动"不同，README 称零售游戏已经能跑：Minecraft Preview 和 Unicorn Overlord 可完整游玩，Fortnite 和 XDefiant 在没有在线服务的前提下能运行到游戏本身允许的程度；另一款较新的零售游戏能进入菜单但尚未进入实际游戏。README 还称某款零售游戏着色器包中的全部 26,698 个 RDNA2 程序都已翻译成 HLSL，并有 370 多个自动化测试。以上均为项目自述，适合对主机逆向和图形管线感兴趣的人围观。

**Why it matters**: 3,631 stars four days after creation. It takes the Wine/Proton route rather than emulation: the Xbox Series CPU is already x64, so the game's code runs natively on a PC with no CPU emulation while XCL stands in for the console libraries a PC doesn't have (`kernelx.dll`, XGameRuntime, `d3d12_xs.dll` and others) and translates the console's RDNA2 GPU machine code to HLSL and then DXIL. Unlike recent projects of the same kind that mostly don't boot yet, the README says retail games already run: Minecraft Preview and Unicorn Overlord are fully playable, and Fortnite and XDefiant work as far as each game goes without its online services; one newer retail game reaches its menus but not gameplay. The README also reports that all 26,698 RDNA2 programs in one retail game's shader pack translate to HLSL, with 370+ automated tests. These are the project's own claims; one to watch for people interested in console reverse engineering and graphics pipelines.

## 8. AFK-surf/xnulinux

⭐ 2,257 · Objective-C++ · 创建于 2026-11-20 · [链接](https://github.com/AFK-surf/xnulinux)

**是什么**：把 XNU 作为可加载内核模块放进 Linux（为 arm64 Linux 提供 macOS 人格）。

**What it is**: XNU as a loadable kernel module inside Linux (macOS personality for arm64 Linux).

**为什么值得关注**：创建四天 2,257 星。它不是虚拟机，也不是在 Linux 上重新实现 macOS 接口，而是从 Apple 公开的源码构建 macOS 的开源内核 XNU，把它作为 `xnu.ko` 模块加载进未经修改的 arm64 Linux 内核。按 README 的说法，被托管的 XNU 直接驱动 CPU 和 MMU，macOS 进程与 Linux 进程在同一批 CPU 上原生并存，中间没有 hypervisor；内存、定时器、文件、网络和 GPU 则由 Linux 通过一个小的接口模块 `fki.ko` 借给 XNU。README 称在原版 Ubuntu 内核上 `insmod xnu.ko` 就能把 Apple 安装器制作的 macOS 27 系统盘启动到桌面，运行 Finder、Safari 和 Chrome，并展示了在 NVIDIA DGX Spark 裸机上运行的截图。这是一个硬核的内核实验，对操作系统研究者很有看头；是否符合 Apple 的软件许可需要使用者自行判断。

**Why it matters**: 2,257 stars four days after creation. It isn't a virtual machine or a reimplementation of macOS interfaces on Linux: it builds XNU, the open-source kernel of macOS, from Apple's published sources and loads it as an `xnu.ko` module inside an unmodified arm64 Linux kernel. According to the README, the hosted XNU drives the CPU and MMU directly, so macOS processes run natively next to Linux processes on the same CPUs with no hypervisor between them, while Linux lends XNU its memory, timers, files, network and GPU through a small interface module, `fki.ko`. The README says that on a stock Ubuntu kernel `insmod xnu.ko` boots a macOS 27 system disk made by Apple's own installer to the desktop, running Finder, Safari and Chrome, and shows screenshots of it running on a bare-metal NVIDIA DGX Spark. It's a hardcore kernel experiment with a lot for OS researchers to dig into; whether a given use fits Apple's software license is for the user to judge.

## 🎙️ Builders 动态 / What Builders Are Saying

**OpenAI CEO Sam Altman**：他贴出一段带引号的主张：前沿模型开发者应共同建立评估这类模型、并对其安全论证做红队测试的共同规范，包括共同的透明度标准；并提议设立基于困惑度（perplexity）等度量的共同上限，在理解和监控 AI 行为的能力达到某个具体里程碑（例如出现思维链监控的继任方案）之前，各家承诺不越过这条线。他随后补充，各实验室已在"白宫协议"下同意建立提升系统安全性的标准和最佳实践，认为讨论使用困惑度有助于推进这些目标。[提议](https://x.com/sama/status/2124551883130114403) · [补充](https://x.com/sama/status/2124558713646428663)

**Sam Altman, CEO of OpenAI**: He posted a quoted statement arguing that frontier model developers should jointly establish shared norms for evaluating such models and red-teaming their safety cases, including shared transparency standards, and proposing common limits based on perplexity and other measurements that developers commit not to cross until the ability to understand and monitor AI behavior reaches a concrete milestone (such as a successor to chain-of-thought monitors).
