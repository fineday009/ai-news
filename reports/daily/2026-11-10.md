## 1. deepseek-ai/dsh-superagent-prototype

⭐ 21.8k · TypeScript · 创建于 2026-10-31 · [链接](https://github.com/deepseek-ai/dsh-superagent-prototype)

**是什么**：DeepSeek 团队放出的研究原型——一个面向单个 GitHub 仓库的"主动式"编码 Agent，打包成 DeepSeek Harness 的 bundle。它监听 GitHub（可选飞书），有授权的人提出需求时，它开一个工单、在独立会话和目录里完成工作，再回到原对话里交付（例如一个 PR）；网页面板只显示需要人处理的事项。

**What it is**: A research prototype from DeepSeek's team—"towards a more autonomous agent system": a proactive coding agent for one GitHub repository, packaged as a DeepSeek Harness bundle. It listens to GitHub (and optionally Feishu); when an allowed person asks for work, it opens a work item, does it in its own agent session and directory, and answers in the original conversation, e.g. with a pull request. A web panel shows only what needs a person.

**为什么值得关注**：11 月 1 日上日报时 3.1k 星，九天后已达 2.18 万，是近期新建 AI 仓库里势头最猛的之一，也已开始被社区产品化（如 11 月 4 日日报提到的衍生项目）。核心理念是"占用尽量少的人类注意力、交付尽量多的价值"：只在被请求或团队写下的规则允许时行动，只在有人必须行动或能用上结果时开口。官方明确说这是研究代码、非正式产品，但它是前沿实验室公开"团队级自主 Agent"工作方式的一手样本。

**Why it matters**: It had 3.1k stars when it made the daily on November 1 and has 21.8k nine days later, one of the strongest runs among recent new AI repos, and the community has already started productizing it (see the derivative project in the November 4 daily). Its core principle is "take as little human attention as possible, give as much value as possible": it acts only when asked or when a team-written rule allows it, and speaks only when someone must act or can use a result. DeepSeek is explicit that this is research code, not an official product, but it's a first-hand look at how a frontier lab works with a team-level autonomous agent.

## 2. N1nEmAn/sapper-v2

⭐ 1.8k · Python · 创建于 2026-10-30 · [链接](https://github.com/N1nEmAn/sapper-v2)

**是什么**：自主渗透测试"军团"——一个 AI 指挥官 + 并行作战的 worker 集群 + 分层事实-意图图谱的多 Agent 编排框架；第三届腾讯云智能攻防挑战赛线上赛冠军。

**What it is**: Autonomous pentest legion — an AI commander plus a worker swarm and a layered fact-intent graph; champion of the 3rd Tencent Cloud Intelligent Attack-Defense Challenge online qualifier.

**为什么值得关注**：README 给出的战绩很具体：634 支队伍中以 80.18/100 夺冠，8 小时全程无人值守；与亚军拿下同样 85 个 flag、快 25 秒，只用了 10 亿 token（对方 45 亿）。它强调自己"是编排框架而不是单个 Agent"：指挥官读盘、决策、派单，将领和士兵并行进攻，一个零策略的看门狗负责保活，所有知识沉淀进分层事实图谱——个体会死，图谱留下；每个角色背后的 CLI（Claude Code、Codex 等）和模型都可替换。想把这套机制用于非攻防场景，作者另开了通用底座 nvwabase。仅限授权安全测试。

**Why it matters**: The README's results are concrete: first of 634 teams at 80.18/100, eight hours fully unattended; the same 85 flags as the runner-up, 25 seconds faster, on 1B tokens where they burned 4.5B. It insists it is an orchestration harness, not a single agent: a commander reads the board, decides and dispatches, generals and soldiers attack in parallel, a zero-strategy watchdog keeps everyone alive, and all knowledge settles into a layered fact graph—individuals die, the graph survives. The agent CLI (Claude Code, Codex and others) and model behind every role are swappable, and for non-pentest uses the author offers a general base, nvwabase. Authorized security testing only.

## 5. garrytan/gbrain

⭐ 32.2k（今日 +216）· TypeScript · [链接](https://github.com/garrytan/gbrain)

**是什么**：Garry Tan 的"OpenClaw/Hermes Agent 大脑"——给你正在用的 Agent 一份由你掌控的记忆：存储带出处的明确事实，支持更正与撤回，并在多个 Agent 之间共享。

**What it is**: Garry's opinionated OpenClaw/Hermes agent brain: give the agent you already use a memory you control. GBrain stores explicit facts with their sources, supports corrections and withdrawal, and makes the same memory available across your agents.

**为什么值得关注**：与"把会话自动压缩成记忆"的思路不同，GBrain 强调可追溯和可纠正的显式事实记录。它从无需密钥的关键词检索起步，按需再加语义搜索、综合和后台补全；`gbrain mcp expose` 一条命令就能通过 Tailscale 把本机的"大脑"以 MCP 形式提供给各处的 Agent。作者称它是自己 OpenClaw 和 Hermes 部署背后的生产系统：155,795 个页面、24,589 个人物、5,340 家公司、66 个定时任务。MIT 协议可自托管，gbrain.io 为可选的付费托管。

**Why it matters**: Unlike approaches that auto-compress sessions into memory, GBrain centers on explicit, traceable, correctable facts. It starts with keyless keyword retrieval and adds semantic search, synthesis and background enrichment when you need them; a single `gbrain mcp expose` publishes the brain on your machine over MCP on your Tailscale tailnet for agents anywhere. The author says it's the production brain behind his OpenClaw and Hermes deployments: 155,795 pages, 24,589 people, 5,340 companies and 66 cron jobs. It's MIT-licensed and self-hostable, with gbrain.io as optional paid hosting.

**是什么**：用代码拍的电影——短片、长 YouTube 视频、广告、讲解片和 MV：你提供想法和品味，AI 编码 Agent 写剧本、用代码搭建每一帧、设计声音，最后交给你一个成片 MP4。

**为什么值得关注**：它在本机的 Claude Code 或 Cursor 里运行，每一帧都在无头 Chrome 中由代码生成（three.js + ffmpeg），不需要付费服务，旁白可选用自己的 Gemini 或 ElevenLabs。有意思的是它对"AI 平庸感"的处理：Agent 会把你的想法和随机抽取的真实事物（博物馆藏品、动物、太空照片等）碰撞，避免给出人人都会想到的版本；正式成片前先让你确认前两个场景；长视频模式会给涉及真人真事的每条陈述附上来源，并按 −14 LUFS 做响度母带。

What's interesting is how it fights AI blandness: the agent collides your idea with a randomly drawn real-world thing (a museum object, an animal, a space photo and so on) so you don't get the version everyone would think of first, and you approve the first two scenes before the full build. Its long-form mode sources every claim about real people or events and masters audio to −14 LUFS.

## 10. jhaizhou-ops/S2Arm

⭐ 1.9k · C# · 创建于 2026-11-08 · [链接](https://github.com/jhaizhou-ops/S2Arm)

**是什么**：让你自己的 Switch 游戏原生运行在 iPhone、iPad 和 Mac 上：游戏代码在构建时改写为原生 ARM64，图形直接走 Metal。

**What it is**: Run your own Switch games natively on iPhone, iPad and Mac: game code rewritten to ARM64, graphics direct to Metal.

**为什么值得关注**：它强调"原生移植而非模拟器"：中间没有 CPU 模拟层，系统服务由原生宿主提供，速度、发热和续航因此受益；所有游戏装进同一个 App，只占一个签名名额。Mac 和 Windows 上都有图形化启动器，还提供 `s2armctl` 控制接口，让 AI 助手代为导入、构建、安装并排错，遇到需要本人操作的步骤会停下来。README 称调研了 211 款游戏、首次构建成功率 95%。需自备合法游戏与密钥；上线两天 1.9k 星。

**Why it matters**: It stresses "a native port, not an emulator": there is no CPU emulator in between and system services come from a native host, which is where the speed, heat and battery gains come from; every game goes into one app that takes a single signing slot. There are graphical launchers for Mac and Windows, plus an `s2armctl` control interface so an AI assistant can import, build, install and troubleshoot for you, stopping when a step needs you. The README reports 211 games surveyed with a 95% first-try build rate. You bring your own games and keys; it reached 1.9k stars two days after launch.

一句话结论：AI 时代教工程，教的不是哪个工具，而是 Agent 的核心原理，以及当生成不再是瓶颈时，如何让审查和交付跟上。

- Mihail Eric 在斯坦福开设 CS146S"现代软件开发者"（今年第二次开课），同时是 Monaco（旧金山的 B 轮 AI 原生销售平台）的 AI 负责人。他担心资深工程师用上 Agent 后突飞猛进，而新人被甩开，所以课程作业要求学生给 AI 原生开源项目贡献代码，由维护者审查，把"好软件的心智模型"传下去。
- 他刻意不为任何工具背书：一个能对话、能改文件的编码 Agent，核心只是一个 Agent 循环，不到 200 行就能写出来；教育要做的是剥掉"秘方"，讲清原理。
- 代码审查成了新瓶颈：一天能开 30 多个 PR 时，人要么成为卡点，要么放任自流。他主张在"Agent 就绪"和可验证性上下功夫，让一类变更可以放心自动批准，只在关键处亲自介入；他还发现很多公司真正的阻碍是 CI、合并队列这类基础 DevOps 问题，而不是少一个 bot。
- 关于自建还是采购，他的原则是"buy to learn, build to keep"（先买来学习，再自建长期持有）：Monaco 自建了身兼 AI SRE、客户支持和 QA 的 Slack 机器人 Hal，但代码审查仍在用 Devin。

The takeaway: teaching engineering in the AI era isn't about any one tool. It's about the core principles of agents, and about keeping review and delivery up to speed once generation is no longer the bottleneck.

- Mihail Eric teaches Stanford's CS146S, "The Modern Software Developer" (now in its second run), and is head of AI at Monaco, a Series B AI-native sales platform in San Francisco. Worried that seniors who adopt agents will surge ahead while juniors fall behind, he makes students contribute to AI-native open-source projects where maintainers review their code, passing down mental models of good software.
- He deliberately endorses no tool: a coding agent you can talk to that edits your files is, at its core, just an agentic loop you can write in under 200 lines. Education should peel away the "secret sauce" and teach the principles.
- Code review is the new bottleneck: when you can put up 30+ PRs a day, you either become the choke point or let anything through. He argues for investing in agent readiness and verifiability so some classes of change can be safely auto-approved, keeping humans for what matters. He also finds that what holds many companies back is basic DevOps such as CI and merge queues, not the lack of one more bot.
- On build versus buy, his rule is "you buy to learn and you build to keep": Monaco built Hal, a Slack bot that's part AI SRE, part customer success and part QA, yet still uses Devin for code review.
