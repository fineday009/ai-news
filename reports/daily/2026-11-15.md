## 1. ChromeDevTools/chrome-devtools-mcp

⭐ 56.4k（今日 +664）· TypeScript · [链接](https://github.com/ChromeDevTools/chrome-devtools-mcp)

**是什么**：给编码 Agent 用的 Chrome DevTools：以 MCP 服务器和 CLI 两种形式，让 Antigravity、Claude、Cursor、Copilot 等 Agent 控制并检查一个真实运行的 Chrome。

**What it is**: Chrome DevTools for coding agents—available as an MCP server and a CLI, it lets your coding agent (such as Antigravity, Claude, Cursor or Copilot) control and inspect a live Chrome browser.

**为什么值得关注**：由 Chrome DevTools 团队官方维护，把 DevTools 的完整能力交给 Agent：录制性能 trace 并提炼可执行的优化建议，分析网络请求、截图、读取带 source map 堆栈的控制台消息，再用 Puppeteer 做会自动等待结果的可靠自动化。对"Agent 写完前端却看不到运行效果"的问题，它比纯截图方案更接近人类工程师的调试方式。注意它会把浏览器里的内容暴露给 MCP 客户端，且默认收集使用统计（可用 `--no-usage-statistics` 关闭）。

**Why it matters**: Maintained by the Chrome DevTools team itself, it hands agents the full power of DevTools: record performance traces and extract actionable insights, analyze network requests, take screenshots and read console messages with source-mapped stack traces, and automate reliably with Puppeteer, which waits for action results. For the "agent wrote the frontend but can't see it run" problem, it's much closer to how a human engineer debugs than screenshots alone. Note that it exposes browser content to MCP clients and collects usage statistics by default (opt out with `--no-usage-statistics`).

## 3. Tencent/LoopForge

⭐ 978（今日 +33）· Go · [链接](https://github.com/Tencent/LoopForge)

**是什么**：自托管的编码 Agent 交付工作台：编排 CodeBuddy、Codex、Claude Code 等 Agent，配合脚本和人工审批节点完成从需求到 PR 的交付。

**What it is**: Self-hosted workflows for coding-agent delivery: orchestrate CodeBuddy, Codex and Claude Code with scripts and human approval gates, from requirement to pull request.

**为什么值得关注**：今日涨幅不大，入选靠的是思路。让 Agent"修个 bug"，结果取决于那一次运行——可能跳过计划、忘了测试、自己审自己的代码。LoopForge 的回答是 SOP：把规划、实现、评审、测试拆成各自有提示词、模型和工具的角色，按固定节点在 Docker 沙箱里执行，关键处设人工审批门，可暂停、重试或从任一节点重跑；聊天里摸索出的好做法也能存成 SOP 复用。支持 10 种编码 Agent CLI，MIT 协议。

**Why it matters**: Today's gain is small; it's here for the idea. Ask an agent to "fix this bug" and the result depends on that run—it might skip the plan, forget the tests or review its own code. LoopForge's answer is the SOP: planning, implementation, review and testing become separate roles with their own prompts, models and tools, run as fixed nodes in Docker sandboxes with human approval gates where they matter, and you can pause, retry or rerun from any node; a way of working found in chat can be saved as an SOP for reuse. It supports ten coding-agent CLIs and is MIT-licensed.

**是什么**：给 computer use Agent 用的独立 macOS 桌面，可以在终端里查看和控制。

**What it is**: A separate macOS desktop for computer-use agents, viewed and controlled from a terminal.

**为什么值得关注**：让 Agent 操作你自己的 Mac，最怕它抢鼠标、动剪贴板、碰到你已登录的账号。terminal-mac 用 Apple Virtualization 跑一台真正的 macOS 虚拟机，由虚拟机内的辅助程序截屏并注入输入，终端里通过 Kitty/iTerm2 图形协议实时显示画面；Agent 命令不会移动宿主机指针或改动剪贴板，客户机有自己独立的应用、文件和账号。目前是面向 Apple 芯片的早期候选版本。

**Why it matters**: The worry with letting an agent drive your own Mac is that it grabs the pointer, touches the clipboard or reaches your signed-in accounts. terminal-mac runs a real macOS guest with Apple Virtualization; a helper inside the guest captures its screen and posts input, and a terminal viewer streams it via Kitty or iTerm2 graphics. Agent commands never move the host's pointer or change its clipboard, and the guest has its own apps, files and accounts. It's an early release candidate for Apple silicon.

**Why it matters**: Built in Rust with GTK4, it turns a WiFi audit that normally chains several command-line tools into a GUI; the interface runs as a normal user and launches a small privileged agent via polkit only when needed, so it works on both X11 and Wayland. Linux only, and it needs a wireless card with monitor mode and packet injection. ### 🎧 播客 / Podcast：Training Data ·「A Model For Everyone: How Ronak From Trajectory Is Building Products For Continual Learning」

**一句话**：Trajectory 想让每家公司都能用自己的生产数据训练专属模型，把"训练—评测—部署"闭环做成一键操作，这是它眼中通往持续学习的第一步。

**The takeaway**: Trajectory wants every company to train its own model on its own production data, collapsing train–eval–deploy into a one-click loop—its first step toward real continual learning.

- **现在只是"伪持续学习"**：Ronak（曾在 Windsurf 参与训练自研模型）用地图打比方：如今像去 AAA 领纸质地图，改路线就得整批重来；Trajectory 先做到 MapQuest——人人都能自己训练和定制模型；最终目标是 Google Maps 式的、每次使用都在更新的系统。
- **"Pseudo continual learning" today**: Ronak (who helped train an in-house model at Windsurf) uses a maps analogy: today is like picking up paper maps from AAA, where any route change means a full batch update; Trajectory starts at MapQuest—everyone can train and customize models themselves—with a Google Maps-style system that updates on every trip as the end goal.
- **客户案例**：据他介绍，Harvey 用 Trajectory 训练的模型比前沿模型便宜约 6 倍，在其法律 Agent 基准上从开源模型的约 4% 提升到约 18%；金融 Agent 公司 Rogo 训出的模型在 token 效率上高出数倍，更快也更便宜。他设想的终局是：10% 的任务交给 Fable 这样的前沿模型，90% 路由到自己训练的高效模型。
- **Customer stories**: By his account, Harvey's Trajectory-trained model is about six times cheaper than the frontier and goes from roughly 4% (an open-source model) to roughly 18% on its legal agent benchmark; finance-agent company Rogo trained a model several times more token-efficient, also faster and cheaper. His end state: send 10% of tasks to a frontier model like Fable and route 90% to an efficient model you trained yourself.
- **三样原料，两处研究**：公司需要生产轨迹（traces）、可回放的环境、以及训练算法。为摆脱对环境的依赖，他们改造 GRPO，做到"组大小为 1"——从上万条各不相同的单次轨迹中学习，而不必把同一任务重放 8 或 16 次；为减少奖励标注，只让客户为精选的约 100 条轨迹写评分标准，再训练一个元评分器推广到全部 1 万条。
- **Three ingredients, two research bets**: Companies need production traces, replayable environments and a training algorithm. To drop the environment requirement they modified GRPO to work at "group size one"—learning from 10,000 single rollouts of different tasks instead of replaying one task 8 or 16 times; to cut reward labeling, customers write rubrics for about 100 well-chosen traces and a meta-grader trained on those propagates reward to all 10,000.
- **持续学习而非递归自我改进**：他把持续学习与 RSI 区分开——RSI 是把模型关进黑箱让它自我改进，令人担忧对齐问题；持续学习则是从与人的真实交互中学习、让人留在回路里。他还认为产品人将变成"园丁"：设好棚架，让产品依据真实使用自我生长。
- **Continual learning, not recursive self-improvement**: He contrasts the two—RSI puts a model in a black box to improve itself, raising alignment worries, while continual learning learns from real interactions with people and keeps humans in the loop. Product builders, he says, become gardeners: set the trellises and let the product grow from real use.
