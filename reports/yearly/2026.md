## 1. openclaw/openclaw

⭐ 383.4k · 创建于 2025-11-24 · TypeScript · [链接](https://github.com/openclaw/openclaw)

**是什么**：属于你自己的个人 AI 助理，支持任意操作系统、任意平台——「龙虾之道」。

**What it is**: Your own personal AI assistant. Any OS. Any Platform. The lobster way.

**为什么值得关注**：本年度当之无愧的第一，38 万星的体量把「本地优先、数据自主的个人 AI 助理」推到了主流视野。它证明了在闭源大厂助理之外，一个开源、跨平台、你拥有全部数据的替代方案，能够聚集起真正的社区规模。

**Why it matters**: The undisputed number one of the year — 383k stars have pushed "local-first, data-sovereign personal AI assistant" into the mainstream. It proves that beyond closed big-lab assistants, an open, cross-platform alternative where you own all your data can gather genuine community scale.

**Why it matters**: As harnesses proliferate (Claude Code, Codex, Cursor…), ECC bets on being the cross-harness performance layer — packaging skills, memory and security into a portable enhancement. 231k stars shows developers want not just one tool but a set of best practices that works across all of them.

## 4. NousResearch/hermes-agent

⭐ 216.9k · 创建于 2025-07-22 · Python · [链接](https://github.com/NousResearch/hermes-agent)

**是什么**：会随你一起成长的 Agent。

**What it is**: The agent that grows with you.

**为什么值得关注**：出自 Nous Research，把「个性化、随使用而演进」作为核心命题。相比一次性的对话 Agent，「成长型」强调长期记忆与用户共同演化，是对「Agent 该如何变得越来越懂你」这一根本问题的开源作答，全年积累近 22 万星。

**Why it matters**: From Nous Research, it makes "personalization that evolves with use" the central premise. Against one-off conversational agents, a "growing" agent emphasizes long-term memory and co-evolution with its user — an open-source answer to the fundamental question of how an agent should come to understand you better over time. Nearly 217k stars across the year.

## 5. github/spec-kit

⭐ 122.1k · 创建于 2025-08-21 · Python · [链接](https://github.com/github/spec-kit)

**是什么**：帮你上手「规范驱动开发（Spec-Driven Development）」的工具包。

**What it is**: Toolkit to help you get started with Spec-Driven Development.

**为什么值得关注**：GitHub 官方出品，回答了 vibe coding 时代的一个核心问题：当 AI 能写代码，人该写什么？答案是写规范。把需求、约束、验收标准结构化成「spec」，让 Agent 有明确的目标去执行，是把 AI 编码从「碰运气」拉回工程纪律的关键方法论，全年 12 万星。

**Why it matters**: An official GitHub project answering a core question of the vibe-coding era: when AI can write code, what should humans write? The answer is specs. Structuring requirements, constraints and acceptance criteria into a "spec" gives agents a clear target to execute against — a key methodology for pulling AI coding back from guesswork into engineering discipline. 122k stars across the year.

## 6. farion1231/cc-switch

⭐ 118.7k · 创建于 2025-08-04 · Rust · [链接](https://github.com/farion1231/cc-switch)

**是什么**：一个跨平台桌面「全家桶」助手，统一管理 Claude Code、Codex、OpenCode、OpenClaw、Gemini CLI 与 Hermes Agent。

**What it is**: A cross-platform desktop all-in-one assistant for Claude Code, Codex, OpenCode, OpenClaw, Gemini CLI and Hermes Agent.

**为什么值得关注**：当开发者同时用五六个编码 Agent、在多个模型供应商之间切换，配置与账号管理本身就成了负担。cc-switch 用一个 Rust 桌面应用把这些统一起来，切中「多 Agent 时代的运维琐事」这一真实痛点，全年近 12 万星，是纯工具类项目里最成功的一个。

**Why it matters**: When developers run five or six coding agents at once and switch between model providers, configuration and account management become a burden in themselves. cc-switch unifies all of it in one Rust desktop app, hitting the real pain of "multi-agent-era housekeeping." Nearly 119k stars across the year makes it one of the most successful pure-tooling projects.

## 8. thedotmack/claude-mem

⭐ 87.8k · 创建于 2025-08-31 · JavaScript · [链接](https://github.com/thedotmack/claude-mem)

**是什么**：为每个 Agent 提供跨会话的持久上下文——捕捉会话中的一切，用 AI 压缩，再把相关上下文注入未来会话。

**What it is**: Persistent context across sessions for every agent — captures everything during sessions, compresses it with AI, and injects relevant context back into future sessions.

**为什么值得关注**：Agent 最大的缺陷之一是「失忆」——每次开新会话都从零开始。claude-mem 把记忆做成跨会话、跨工具（Claude Code、Codex、Gemini、Copilot…）的通用层，是 2026 年「Agent 记忆」赛道最有代表性的开源方案，全年近 8.8 万星。

**Why it matters**: One of an agent's biggest flaws is amnesia — starting from zero each new session. claude-mem builds memory into a universal, cross-session, cross-tool layer (Claude Code, Codex, Gemini, Copilot…), making it the most representative open-source answer in 2026's "agent memory" lane. Nearly 88k stars across the year.

## 10. rtk-ai/rtk

⭐ 71.7k · 创建于 2026-01-22 · Rust · [链接](https://github.com/rtk-ai/rtk)

**是什么**：一个 CLI 代理层，在常见开发命令上把 LLM 的 token 消耗降低 60–90%——单个 Rust 二进制、零依赖。

**What it is**: CLI proxy that reduces LLM token consumption by 60-90% on common dev commands. Single Rust binary, zero dependencies.

**为什么值得关注**：Agent 用得越多，token 成本越成为真实的经济约束。rtk 从「命令输出压缩」这个刁钻角度切入——在 git、build、test 等高频命令上大幅削减喂给模型的 token，直接省钱省上下文。单二进制、零依赖的工程取向让它极易落地，全年逾 7 万星，是「降本」方向最典型的基础设施。

**Why it matters**: The more agents are used, the more token cost becomes a real economic constraint. rtk attacks from a clever angle — command-output compression — cutting the tokens fed to the model on high-frequency commands like git, build and test, directly saving money and context. Its single-binary, zero-dependency approach makes it trivial to adopt. Over 71k stars across the year make it the archetypal "cost-reduction" infrastructure.
