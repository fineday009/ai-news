## 1. openclaw/openclaw

⭐ 382k · 创建于 2025-11-24 · TypeScript · [链接](https://github.com/openclaw/openclaw)

**是什么**：本地优先的个人 AI 助手平台，把 WhatsApp、Telegram、Slack、Discord 等多渠道对话统一接入一个 AI Agent 后端，支持语音与 Agent 沙箱。

**What it is**: A local-first personal AI assistant platform that unifies multi-channel conversations (WhatsApp, Telegram, Slack, Discord, etc.) into one AI-agent backend, with voice and agent sandboxing.

**为什么值得关注**：本年新建仓库的星标之王，也是一场现象级运动。它把「自托管、隐私优先的私人助手」从愿景变成成熟工程——数万提交、文档完备、社区活跃，代表了 2026 年最强的一股「拥有你自己的 AI」思潮。

**Why it matters**: The star king among repos created this year and a genuine phenomenon. It turns "self-hosted, privacy-first personal assistant" from vision into mature engineering — tens of thousands of commits, full docs, active community — embodying 2026's strongest "own your AI" current.

## 2. NousResearch/hermes-agent

⭐ 212k · 创建于 2025-07-22 · Python · [链接](https://github.com/NousResearch/hermes-agent)

**是什么**：Nous Research 打造的「会随你成长」的自我改进 AI 助手，跨 CLI、Telegram、Discord、Slack 等平台运行，具备自建技能的学习循环、跨会话持久记忆、定时任务与并行子 Agent。

**What it is**: A self-improving AI assistant from Nous Research that runs across CLI, Telegram, Discord, Slack and more, with a skill-learning loop, cross-session persistent memory, scheduled tasks, and parallel subagents.

**为什么值得关注**：它把「Agent 从经验中积累程序性记忆并不断变强」做成了产品级能力，且不绑定单一模型厂商。相比无状态聊天机器人，这种「越用越懂你」的路线是过去一年 Agent 形态最重要的进化方向之一。

**Why it matters**: It productizes "an agent that accumulates procedural memory from experience and keeps getting better," without locking to one model vendor. Versus stateless chatbots, this "learns you over time" path is among the year's most important shifts in agent form.

## 3. github/spec-kit

⭐ 119k · 创建于 2025-08-21 · Python · [链接](https://github.com/github/spec-kit)

**是什么**：GitHub 官方推出的「规格驱动开发（Spec-Driven Development）」工具包，帮你用规格先行的方式指挥 AI 编码。

**What it is**: GitHub's official toolkit for Spec-Driven Development — steering AI coding through a spec-first workflow.

**为什么值得关注**：当「vibe coding」暴露出不可控的一面，业界开始回归工程纪律；spec-kit 由 GitHub 官方背书，把「先写规格、再让 Agent 实现」标准化，是今年「让 AI 编码可控」思潮里最有影响力的方法论工具。

**Why it matters**: As "vibe coding" showed its uncontrollable side, the field swung back toward engineering discipline; officially backed by GitHub, spec-kit standardizes "write the spec, then let the agent implement," making it the year's most influential methodology tool for controllable AI coding.

## 4. karpathy/autoresearch

⭐ 90.6k · 创建于 2026-03-06 · Python · [链接](https://github.com/karpathy/autoresearch)

**是什么**：让 AI Agent 在单张 GPU 上自主开展机器学习研究——自动修改训练代码、跑实验、按指标迭代，一夜可跑约 100 组实验。

**What it is**: Lets AI agents autonomously do ML research on a single GPU — modifying training code, running experiments, and iterating on metrics; ~100 experiments overnight.

**为什么值得关注**：Karpathy 出品，把「AI 做 AI 研究」这一命题落到极简、可复现的实现上（固定 5 分钟训练预算、以 bits-per-byte 为指标）。它不追求炫技，而是给自动化科研提供了一个人人能跑的干净基线。

**Why it matters**: From Karpathy, it grounds "AI doing AI research" in a minimal, reproducible implementation (fixed 5-minute training budget, bits-per-byte metric). Not a flex — a clean, runnable baseline for automated research anyone can reproduce.

## 5. thedotmack/claude-mem

⭐ 86.6k · 创建于 2025-08-31 · JavaScript · [链接](https://github.com/thedotmack/claude-mem)

**是什么**：为各类 Agent 提供跨会话持久上下文——捕获 Agent 会话中的一切，用 AI 压缩后，把相关上下文注入未来会话。兼容 Claude Code、Codex、Gemini、Copilot 等。

**What it is**: Persistent context across sessions for any agent — captures everything an agent does, compresses it with AI, and injects relevant context into future sessions. Works with Claude Code, Codex, Gemini, Copilot and more.

**为什么值得关注**：「上下文会话即失忆」是 Agent 落地的核心痛点，claude-mem 把记忆做成可插拔的中间层，跨工具通用。它是这一年「Agent 记忆」赛道里采用最广的开源方案之一。

**Why it matters**: "Amnesia between sessions" is a core blocker for real agent use; claude-mem makes memory a pluggable middle layer that works across tools. One of the most widely adopted open memory solutions of the year.

## 6. rtk-ai/rtk

⭐ 69.3k · 创建于 2026-01-22 · Rust · [链接](https://github.com/rtk-ai/rtk)

**是什么**：一个 CLI 代理，在常见开发命令上把 LLM 的 token 消耗降低 60–90%，单个 Rust 二进制、零依赖。

**What it is**: A CLI proxy that cuts LLM token consumption by 60–90% on common dev commands — a single Rust binary, zero dependencies.

**为什么值得关注**：当 Agent 编码普及，token 成本成了真金白银的痛点。rtk 从命令输出这一侧做压缩，几乎无侵入即可省钱。今年涌现大量「省 token」项目，rtk 是其中最简洁高效的代表之一。

**Why it matters**: As agentic coding spreads, token cost becomes a real-money pain. rtk compresses on the command-output side, saving money with almost no intrusion. Among the year's many "token-saving" projects, it's one of the leanest and most effective.
